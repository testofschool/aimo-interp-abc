                                                   Abstract

            We audit public labels used to develop robustness predictors for the AIMO In-
            terpretability Challenge. On the competition-checkpoint training data, a descrip-
            tive problem-mean decomposition accounts for 0.7822 of observed maximum-
            drop variance across 76 repeated-configuration rows. Among labelled Small-track
            problems represented by multiple checkpoints, 11/11 have concordant labels. A
            problem-only logistic control using log character length and digit count achieves
            leave-one-problem-out balanced accuracy 0.6855 and plain accuracy 0.7674, with
            wide problem-clustered intervals. These observations motivate explicit problem-
            only controls; they establish neither a model-internal signal nor performance on
            unseen private competition problems. Public sample panels show different as-
            sociations and weak control transfer. Private-validation and final-test results re-
            main unmeasured. We provide a hash-pinned CPU reproduction package and dis-
            tinguish observed calculations, contextual baseline reports, and experiments that
            were not executed.


1    Task, data, and scope

The challenge asks whether a model answers a mathematical problem robustly under meaning-
preserving perturbations. Its Small track evaluates Qwen3.5-4B, Skywork-OR1-Math-7B, Olmo-
3-7B-Think, and DeepSeek-R1-0528-Qwen3-8B; the Main track adds gpt-oss-120b with several
reasoning efforts. Competition ranking uses plain accuracy on held-out problem-model instances.
We also report balanced accuracy because prevalence differs across public panels. [1, 2]
The pinned train-main-v2 table has 94 rows over 36 problems, including 80 labelled rows over
33 problems and 14 unlabelled rows. Our public Small evaluation cohort is 43 labelled rows over
22 problems, with 31 robust and 12 non-robust labels. This is public training data, not the private
scoring set. The dataset card states the labelled-row rule verbatim:
is_robust = true iff max_drop <= 0.10
is_robust = false iff max_drop >= 0.25
The intervening band carries null labels. This public rule does not disclose the private-label proce-
dure: the current website says the exact evaluation criterion is unpublished. Public samples contain
additional configurations and closed API models. The starter README says low-suffixed sam-
ple names and closed API models are never passed during the Competition phase; sample findings
below are development caveats. [1, 2, 3]

2   Problem identity and observed label agreement
Our descriptive R-squared is one minus within-problem squared error divided by total squared error,
using the same rows to estimate each problem mean and its residuals. This is an in-sample decompo-

are observed. The registered repeated-configuration cohort has 76 rows over 18 problems; 3 of these
problems have only gpt-oss effort variants. Calling all of them multi-model would be inaccurate.

A group is concordant when all included binary labels agree. The reference sums the probability
of all-positive or all-negative labels at each observed group size, assuming independent Bernoulli
draws at pooled panel prevalence. It is not a p-value. The no-gap sensitivity labels every training row
robust iff its drop is at most 0.10, then collapses gpt-oss efforts by minimum label. Any non-robust
effort makes that checkpoint non-robust. Both cohort and collapse rule change; this is not identical
agreement under the original labels. Sample-full proxy labels use the public threshold band and are
not private competition labels.
Raw val-sample agreement is 1/6; removing duplicate model-problem pairs changes it to 0/5.
Duplicate configurations can change the apparent number of repeated groups.

3   A problem-only control and its uncertainty
Features are log-one-plus character length and digit count of the original problem. Class-balanced
logistic regression with default regularization and a fixed convergence limit is fitted using the 80
labelled Main-table rows. Each leave-one-problem-out fold excludes every row with the held-
out problem string, including gpt-oss efforts. We score only the 43 labelled Small rows: pooled-
checkpoint training, Small-only evaluation. The threshold is 0.5. There is no hyperparameter search
or model-internal input.
The control correctly classifies 27 robust and 6 non-robust rows; its plain-accuracy improvement
is small in case count. We hold OOF predictions fixed, sort the 22 problem strings, and draw that
many clusters with replacement using NumPy default_rng, seed 0, for 4000 replicates. All rows

5   Unscored sample-panel caveats
The 141-row aggregate sample has 36 robust list-formatted rows and 105 non-robust string-
formatted rows, with no opposite-label cases. A flag for whether permutation_type starts with an
opening bracket achieves balanced and plain accuracy 1.0; majority-label plain accuracy is 0.7447.
This is perfect observed association, not evidence of a causal construction mechanism. That field is
not the original problem-only input available to a deployed control.
On these rows, five-fold StratifiedGroupKFold grouped by problem ID gives the text control
mean balanced accuracy 0.6754 and mean plain accuracy 0.6865 across ten seeds; balanced accu-
racy ranges from 0.6159 to 0.6996. Dataset and splitter family match the organizer artifact; actual
folds and full pipeline are not claimed identical. Format and majority rules show why this compari-
son cannot alone establish interpretability. These sample configurations are not scored competition
inputs. [3, 5]

6   External attempts and overlapping public work
Inherited screening considered external mathematical difficulty, self-generated perturbation labels,
and public generation dumps. These were planning decisions, not completed target-checkpoint ex-
periments in this run. The packet lacks executable Omni-MATH predictions and a fully specified
Monte Carlo label-noise simulation; we omit their quantitative claims. A difficulty proxy need not
predict perturbation sensitivity, and synthetic-label agreement cannot be assumed from sample count
alone.
One diagnostic is reproducible: on 24 deduplicated val-sample pairs, observed unperturbed accu-
racy has AUROC 0.7333 for the robust label; 8 of 15 non-robust pairs have perfect observed base
accuracy. This uses organizer outcome metadata, not deployable problem-only features, on public
sample configurations. No external source was validated here as replacement target-label data. No
new white-box experiment or ablation was run; that absence is not evidence that white-box signals
have no effect.
Public participants already discuss these risks. Byeolki reports within-problem label agreement and
difficulty shortcuts on an earlier cohort. Coderdailyone reports strong text cross-validation followed
by weaker public leaderboard performance. Renx reports poor probe behavior under distribution
shift relative to a constant rule. We cite these overlaps without a comprehensive novelty claim. Our
contribution is an explicit reproduction and sensitivity ledger for the pinned public files. [7, 8, 9]
