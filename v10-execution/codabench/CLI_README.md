# Local Codabench H1 uploader

`python tools/codabench_v101_upload.py --check-local` checks the three immutable ZIPs, root empty small.txt, CRC and committed preregistration without network or authentication. The current local result is in CLI_CHECK_LOCAL.json. The implementation is prepared only; no authenticated execution or upload has occurred during preparation.

Run `python tools/codabench_v101_upload.py --run` with a Python environment containing requests, **only in Felix's local interactive terminal**. The password prompt accepts the testofschool password once using getpass. Never paste a password, token, session cookie or recovery key into chat. The program refuses non-TTY input before reading a password. It first checks local files and successfully reads the login form; then it prompts locally. It clears/closes in-memory sessions when the run exits and never saves credentials or authenticated HTML.

The program checks authenticated username testofschool; server-scoped own submissions and every row.owner; current phase/task/deadline; and all possible existing matching filenames before any upload. A unique exact filename with verified owner, phase and Small task can link an existing native receipt and skip a new upload; it is not proof of server ZIP SHA. Multiple matches, a contradictory supplied hash/size, or an unverified task mean HOLD. An ambiguous or uncertain mutation is never retried automatically. A nonblocking local flock prevents concurrent uploader processes. Every upload mutation is single-attempt, and its intent is atomically journaled before the request. Login is a separate single-attempt authentication request. Signed storage URLs use a separate cookie-free session and are neither printed nor persisted.

`v9-execution/official-upload-journal.json` records sanitized request states and accepted submission ids. If a run stops after any mutation intent, reconcile the native own submission list and journal before attempting further uploads; the program stops on unresolved pending states. Do not delete the journal or rerun to manufacture a fresh attempt. The pre-score protocol remains unchanged. Native created_when is compared with the actual preregistration commit time. A prior submission that predates preregistration is exploratory; an externally found probe with unknown prior exposure is EXPLORATORY_OR_UNVERIFIED. Resuming the same known accepted journal id preserves its chronology classification. Missing native times remain UNKNOWN.

New submission POSTs are spaced at least 120 seconds apart. Own status is polled every 120 seconds for at most 60 minutes per bundle; a still-running bundle is preserved and processing can continue. Mutations stop at 2026-11-01 20:00 KST, before the phase's 20:55 KST end. `SCORES.json` is created only from native accepted ids and owned responses. Raw decimal scores are preserved, while k, N and coverage remain unknown until a scoring contract proves their meaning. The program never reads leaderboard data, protected labels, or other participants' results.

Synthetic failure tests in test_upload_safety.py do not use network, authentication or official outcome fixtures.

The API source can create children for multiple tasks or queues. The uploader distinguishes the accepted parent id from a proven Small score submission id; it holds on unexpected tasks or multiple Small score children. Actual native completion time is unknown and remains null; first observation of Finished has its own observed_finished_KST field.
